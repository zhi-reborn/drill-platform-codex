# 大屏4独立副本设计

## 目标

在指挥监控页“大屏3”按钮右侧增加“大屏4”入口。大屏4初始展示、交互和数据来源与大屏2一致，但页面组件、模板、脚本逻辑和样式均独立；后续修改任一页面的前端元素，都不影响另一个页面。

## 方案

- 新建 `web/src/views/director/ScreenView4.vue`，以当前 `ScreenView2.vue` 为初始完整副本。
- 新增指挥端子路由 `/director/screen4/:id`，直接加载 `ScreenView4.vue`。
- 在 `MonitorView.vue` 的“大屏3”右侧增加“大屏4”按钮，使用独立样式类，并通过 `window.open` 在新标签页打开对应演练的大屏4。
- 大屏4继续直接调用与大屏2相同的演练详情、步骤、日志和 WebSocket 数据源。两者不共享页面组件、页面脚本或页面级样式，因此任一页面的后续前端改动都不会传播到另一个页面。

## 视觉方向

入口按钮保持监控页现有圆角、图标、间距和交互反馈，仅使用与前三个入口协调但可辨识的青绿色强调色。大屏4首版保持大屏2现有视觉效果，不额外改造其信息架构，避免“相同效果”出现偏差。

## 边界与异常处理

- 只有演练 ID 为正整数时才打开新页面，复用现有入口的防护方式。
- 路由继续沿用指挥端权限与布局，不新增后端接口或权限模型。
- 数据加载和实时更新异常处理保持与大屏2当前实现一致。
- 本次不修改大屏2文件，除复制产生的新文件外不进行相关重构。

## 验证

- 测试先证明“大屏4”按钮、跳转函数、独立路由和独立组件尚不存在，再实现使其通过。
- 运行大屏2既有测试，确认复制及路由新增未改变大屏2行为。
- 运行前端类型检查与生产构建。
- 在浏览器中验证“大屏4”位于“大屏3”右侧、点击后打开正确 URL，且页面可正常渲染并与大屏2初始效果一致。

## 完成标准

1. 监控页显示风格协调的“大屏4”按钮。
2. 点击按钮打开 `/director/screen4/<演练ID>`。
3. 路由加载独立的 `ScreenView4.vue`。
4. 大屏4初始功能与大屏2一致，且未来修改大屏2或大屏4的页面代码不会互相影响。
5. 相关测试、类型检查、构建和浏览器验证通过。
