# 大屏4当前环节待完成任务舱设计

## 目标

将大屏4底部现有“演练概览 + 执行日志”区域完整替换为当前环节待完成任务舱，让指挥人员一眼看清正在执行的任务和后续待执行任务。大屏2及公共流程展示逻辑不做改动。

## 范围

- 仅修改大屏4页面及其专属测试代码。
- 复用大屏4已经加载并实时更新的 `steps` 数据，不新增后端接口。
- 不修改大屏2、公共阶段选择逻辑或大屏4跑道组件。
- 原底部演练概览和执行日志从大屏4页面移除，其相关的页面内计算与样式一并清理。

## 数据选择规则

1. 从用户当前选中的阶段中排除阶段同名占位节点，只保留实际业务环节。
2. 优先选择包含 `running` 叶子任务的环节作为目标环节。
3. 如果没有执行中的环节，选择第一个包含 `pending` 叶子任务的环节。
4. 目标环节内只展示 `running` 和 `pending` 叶子任务；`completed`、`skipped`、`timeout`、`issue` 不进入待完成列表。
5. 排序规则为 `running` 在前、`pending` 在后，同一状态内保持原始 `seq` 顺序。
6. 第一项 `running` 任务为主任务；没有 `running` 时，第一项 `pending` 任务为主任务并标记“下一任务”。其余任务进入候场矩阵。
7. 多个任务并行运行时，除第一项外的其他 `running` 任务位于候场矩阵最前，并保留执行中视觉状态。

以上选择逻辑放在大屏4专属的纯函数模块中，便于使用固定数据验证各种状态，同时保持大屏2与大屏4前端实现互不依赖。

## 视觉设计

采用已选定的 A 方案“主任务 + 候场矩阵”，延续现有工业指挥中心风格。

### 容器

- 使用一块全宽任务舱替代原来的左右双面板。
- 青蓝描边、深海军蓝半透明底、细网格纹理与顶部能量线延续跑道视觉。
- 标题区显示“当前环节”、目标环节名称及待完成任务总数。

### 主任务区

- 占任务舱约三分之一宽度，作为视觉锚点。
- 执行中使用琥珀色能量描边、脉冲状态灯和缓慢流动进度光带。
- 下一任务使用青蓝色描边，避免与执行中状态混淆。
- 展示任务序号、名称、状态以及执行组或人员；无人员信息时显示“待分配”。

### 候场矩阵

- 占剩余空间，使用自适应多列网格展示其他待完成任务。
- 每张任务卡展示序号、名称、执行状态与执行组或人员。
- `running` 使用琥珀色强调，`pending` 使用克制的青蓝色；文字过长时单行省略并保留 `title`。
- 超出可见高度时仅矩阵区域滚动，不改变大屏整体高度。

### 动效与可访问性

- 数据切换时任务卡使用轻量淡入上移动画。
- 仅执行中主任务使用持续脉冲，减少无意义动态效果。
- `prefers-reduced-motion` 下关闭循环与入场动画。
- 面板、主任务和候场列表提供清晰的语义标签与状态文本，不依赖颜色表达状态。

## 空状态

- 所选阶段没有业务任务：显示“该阶段暂无任务配置”。
- 阶段存在业务任务但没有 `running` 或 `pending` 任务：显示绿色完成舱“当前阶段待完成任务已清零”。
- 数据加载失败继续沿用页面已有的全屏错误状态，不在任务舱内重复报错。

## 实时更新

任务舱由现有 `steps` 响应式数据派生。WebSocket 或轮询刷新步骤状态后，目标环节、主任务、候场任务和计数自动重算，不维护额外的可变副本。

## 验证

- 纯函数测试覆盖：执行中优先、无执行中时回退首个待执行环节、过滤终态任务、并行执行排序、空阶段与全部清零。
- 页面结构测试覆盖：旧演练概览与日志区域已移除，新任务舱、主任务和候场矩阵存在。
- 运行前端全量测试、类型检查和生产构建。
- 在 `/director/screen4/90` 浏览器实页检查常用分辨率下的信息层级、溢出、空状态和实时数据展示。
