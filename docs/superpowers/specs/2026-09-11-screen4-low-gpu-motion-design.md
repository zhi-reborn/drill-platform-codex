# Screen4 低 GPU 动效优化设计

## 背景与目标

Screen4 当前以跑道流光、节点呼吸、阶段卡片和里程碑仪表盘形成工业指挥舱氛围。页面信息层级与视觉方向保持不变，本次只优化渲染成本，使普通无独立 GPU 的机器也能持续流畅展示，同时尽量保留动态效果。

成功标准：

- 保留跑道能量流、当前节点呼吸、阶段推进和任务吸收反馈。
- 不改变业务数据、交互流程、页面布局和状态颜色语义。
- 减少持续运行的模糊滤镜、大面积重绘及彼此竞争的无限动画。
- 页面不可见时暂停装饰动画，重新可见后自然恢复。
- 保持 `prefers-reduced-motion` 的无障碍降级。
- 现有 Screen4 单元测试通过，前端生产构建通过，并在 `/director/screen4/90` 完成页面观感检查。

## 视觉方向

延续深蓝工业指挥舱风格，以青色表达系统通路、绿色表达完成、橙色表达当前执行。动态视觉形成明确主次：当前阶段和当前节点持续活跃，已完成路径保持低频能量流，其他装饰只保留静态辉光或更慢的节奏。

关键记忆点仍是贯穿页面的蛇形恢复跑道。优化不能把页面变成静态图，也不新增与业务状态无关的装饰。

## 实现方案

### 1. 动效分层

- 将高成本的动态辉光拆分为静态光晕底层和清晰运动芯线。
- 运动层优先只改变 `transform`、`opacity` 或局部 SVG 描边偏移。
- 避免让运动元素同时承担多层 SVG filter 或多重 drop-shadow。
- 保持当前路径的橙色推进、完成路径的绿色流动及节点状态反馈。

### 2. 动画调度

- 在组件根节点维护页面可见状态。
- 监听 `document.visibilitychange`；页面隐藏时为根节点添加暂停状态，统一暂停装饰性 CSS 动画。
- 页面重新可见时移除暂停状态，CSS 动画继续运行。
- Web Animations API 创建的任务吸收动画属于短时业务反馈，不在页面隐藏时创建；组件卸载时清理监听器和临时动画元素。

### 3. 绘制边界

- 为跑道画布和底部任务区域建立合适的 paint/layout containment，限制重绘影响范围。
- 只在确实由合成器驱动的短时或持续运动元素上使用 `will-change`，避免大面积常驻图层。
- 将背景扫描、待执行漂移等大面积 background-position 动画改为伪元素位移，或降低为局部、低频效果。

### 4. 动效节奏

- 当前执行节点、进度头和里程碑保留最高视觉优先级。
- 已完成节点的轨道旋转与能量条减速，避免所有节点同步高频运行。
- 头部阶段卡片和主跑道的装饰动画错开节奏，避免同一时刻集中重绘。
- 不依赖 `hardwareConcurrency` 或 `deviceMemory` 自动分档，避免设备误判导致观感不一致。

## 兼容性与边界

- 不引入 Canvas、WebGL 或新的动画依赖。
- 不修改 Screen4 数据计算、节点布局算法或 WebSocket 更新逻辑。
- 不覆盖工作区中现有的节点名称截断、完整标题提示相关改动。
- 浏览器不支持部分优化属性时，页面仍保持原有布局与可读性。

## 测试与验证

1. 先增加组件源码约束测试，覆盖可见性暂停、动效分层和绘制边界；确认测试因缺少实现而失败。
2. 实施最小样式与生命周期改动，使新增测试通过。
3. 运行 Screen4 相关测试及前端生产构建。
4. 刷新 `/director/screen4/90`，检查布局、色彩、动态主次和低配友好的连续运动；同时确认控制台无新增错误。
