# 进行中环节单列步骤面板设计

## 背景

数据大屏的流程节点默认只渲染前三条步骤，其余内容以“另有 N 个步骤…”代替。正在执行的环节虽然已经改为渲染全部步骤，但聚焦节点会放大到 `1.3` 倍；Chrome 在较矮视口中会把放大后的清单底边和阴影裁掉。步骤继续增多时，清单也会无限向下延伸。

## 目标

- 正在进行的环节保持单列，最多完整展示十条叶子步骤。
- 超过十条时限制清单高度并在清单内部滚动，不让流程轨道或整页滚动。
- 已完成和待开始环节继续展示前三条步骤及剩余数量，保持流程轨道简洁。
- 修复 Chrome 矮视口中的底部裁切，并保留节点圆角和发光阴影。
- 保留现有步骤状态、颜色、图标、文字换行和 `1.3` 倍节点聚焦效果。

## 方案

继续渲染进行中环节的全部步骤，由清单本身控制可见高度：

- `running` 且不超过十条：清单使用自然高度，所有条目完整可见。
- `running` 且超过十条：清单获得滚动状态类，最大高度按十条单列内容设置，并启用 `overflow-y: auto`。
- 其他状态：使用 `node.steps.slice(0, NODE_STEP_LIMIT)`。
- 仅非 `running` 节点在超过限制时渲染“另有 N 个步骤…”。

进行中清单沿用琥珀色工业控制台视觉：单列左对齐、稳定的行间距、细窄发光滚动条和底部内阴影提示。滚动只发生在步骤面板内部，标题、齿轮、连接线和节点聚焦位置保持固定。

`.flow-viewport` 增加与十条单列内容及 `1.3` 倍缩放匹配的底部安全区。安全区同时覆盖清单圆角和外发光，避免依赖特定浏览器或当前四条数据刚好不溢出的偶然布局。

不修改接口、流程数据、环节状态计算、其他节点的信息密度或底部概览/日志面板。

## 验证

- 单元测试覆盖十条以内保持自然高度、超过十条启用内部滚动、非进行中节点仍受三条限制。
- 前端构建通过。
- 在 Chrome 当前矮视口检查 `/admin/screen/90`：四条步骤、底部圆角和阴影完整可见。
- 使用十条和超过十条的测试数据检查：十条完整显示；更多内容只在步骤面板内滚动；节点不遮挡左右两侧的概览和日志区域。
